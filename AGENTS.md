# Электросмета

Этот репозиторий `ivanmetizpro-droid/APP---Alyona` выбран пользователем для приложения электрика. Название репозитория не означает, что здесь нужно создавать CRM риелтора.

## Сначала прочитать

- `docs/TZ_Elektrosmeta_HTML_CSS_JavaScript_Codex.md` — полное ТЗ и критерии C01–C24/A01–A25.
- `docs/PROMPT_CODEX_Elektrosmeta.txt` — исходное задание на реализацию.
- `docs/IMPLEMENTATION_STATUS.md` — фактическая готовность, ограничения и следующий этап.
- `docs/CODEX_ENVIRONMENT.md` — команды подготовки и настройки облачной среды.

## Технологии

HTML5, CSS3, JavaScript ES modules; SVG для редактора; IndexedDB; локальная генерация PDF с кириллицей; офлайн-PWA. Не менять стек на React/Vue, TypeScript или Kotlin без запроса пользователя. Node.js нужен для инструментов разработки, а не для серверной части продукта. Не добавлять Docker и серверную авторизацию.

## Основные ограничения

- Миллиметры для геометрии, копейки для денег; разные сущности для линии, кабеля, трассы, гофры, штробы и крепежа.
- Участок выключатель–светильник проходит по потолку независимо от основной трассы.
- Крепёж только открытой прокладки: 500 мм, +15%. Метизы +15% от базы узлов до запаса крепежа.
- Заделка и расходники только для штроб с включённой заделкой.
- Один прибор учитывается в мощности один раз; сложность применяется один раз к стоимости работ.
- Старые сметы неизменяемы; обновления прайса/библиотек не переписывают snapshots.
- Клиентский PDF из публичного DTO: перечень, объёмы и один итог; без расценок строк, внутренних сумм и срока выполнения.
- Не выдумывать нормы и таблицы допустимых токов. Источники, применимость и непроверенное фиксировать в RULES_VERIFICATION.md.
- Не выдавать стартовую страницу и инфраструктурные smoke-тесты за готовое приложение и его приёмку.

## Команды

Первичная подготовка Linux/Codex: `bash .codex/setup.sh`.
Обновление кешированной среды: `bash .codex/maintenance.sh`.
Проверки: `npm run check`; браузерные проверки: `npm run test:e2e`.
Запуск: `npm run dev` (127.0.0.1:4173).
Локальные PDF-зависимости: `npm run vendor`.

Тестировать существенные расчёты, сохранность данных и экспорт; не заменять их проверкой названий CSS-классов. После изменения запуска/серверных скриптов выполнить инфраструктурные тесты и smoke-проверку. После новых продуктовых функций расширять тесты по соответствующим критериям ТЗ.

Работать по этапам 27 ТЗ до завершения задачи. Фиксировать выполненный этап и доказательства в IMPLEMENTATION_STATUS.md и ACCEPTANCE.md. Не снимать ограничения безопасности и не добавлять секреты в репозиторий. Не выполнять публикацию сайта или отправку документов без отдельной задачи. Сообщать честно о фактически выполненных проверках и блокерах.
